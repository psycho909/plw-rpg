## Standards

**PASS WITH FINDINGS.** The runner uses actual content registries and public `awardContentLoot`, `combatTurn`, `craft`, `simulate`, `serialize`, and `deserialize` APIs. Controlled combat/economy fixtures are labeled and kept separate from long natural background simulation. Canonical source/build/release checks, served-asset byte comparison, unique browser run IDs, append-only logs, and a separate controlled browser context are sound foundations. Existing static typecheck evidence records exit 0 after a narrowly scoped Node declaration shim; this review did not rerun it.

**S1 — P1: formal simulation lanes can pass with zero combat samples or duplicate long-world seeds.** `qa_simulation.test.ts:214-215,217-238` accepts `PHASE7_QA_COMBAT_PER_CELL=0`; the loop emits no rows and the final expectation compares `0` with `monsterCount × 3 × builds × 0`, so it passes. `qa_simulation.test.ts:24,286-310` does not validate seed count, validity, or uniqueness; three repeated seed values produce three nominal 100-year traces but only one independent seed. The J ticket requires a representative combat matrix and three seeds. Validate positive safe-integer samples and exactly three distinct valid seeds before a formal lane can write a successful completion record.

**S2 — P1: current economy lane supplies an unseeded bias material and rejects the public craft.** `qa_simulation.test.ts:251-259` seeds only `recipe.inputs`, then requests `recipe.allowedBiasMaterials[0]`. The public `planCraft` path adds one additional material for an allowed bias (`src/engine/crafting.ts:215-220`). The active Cave Insect recipe's first allowed bias is `cave_insect_chitin`, already seeded at its recipe input amount of two (`src/data/content/caveInsects.ts:113-119`), so the requested biased craft needs a third unit and is rejected for missing material. This will stop the formal economy lane on current content. Either seed and report the separate bias cost in the controlled fixture or request no bias for the base recipe cost case; if bias is a separate case, measure it explicitly.

**S3 — P1: the browser regression can claim PASS without verifying normal-lane save/reload or a valid opening UI.** Default regression duration is 60 seconds (`qa_browser_launcher.py:70-73`), while normal-context reload is scheduled at 300 seconds (`qa_browser_runner.py:375-410`), so its default normal run performs no reload. When a reload does occur, `sameWorldTime` only compares the world-time field and is recorded, not asserted (`qa_browser_runner.py:392-410`). The regression status only checks controlled-fixture statuses (`qa_browser_runner.py:411-414`); a fixture is counted as pass whenever post-reload body text is nonempty (`qa_browser_runner.py:281-294`). The opening control is optional and absence does not fail (`qa_browser_runner.py:356-368`). As written, blank/error UI or corrupted persisted state retaining world time may still be reported as browser regression PASS. Require a visible valid game surface/opening, an actual normal reload in the regression lane, and assertions on stable save/content/UI invariants before returning PASS; controlled fixtures should assert their expected family/content evidence, not just nonempty text.

**S4 — P2: checkpoint telemetry retains and duplicates all cumulative browser event arrays.** `qa_browser_support.py:143-152,155-158` stores every save write, storage error, rejection, and long task for the page lifetime. `qa_browser_runner.py:193-221,340-341` copies those full arrays into each checkpoint and also keeps each complete checkpoint in `status`. During a 20/30-minute lane this creates growing in-memory results and repeated serialized copies (quadratic growth in the number of events/checkpoints), which can inflate the heap/DOM/performance measurements and perturb the stress run. Store deltas or bounded counters/summaries per interval and retain a single append-only raw event stream if full events are needed.

**S5 — P2: `infiniteSupplyArbitrageFlag` overstates the price evidence.** `qa_simulation.test.ts:269-283` compares catalog `sell` values for input/output plus recipe gold. It does not use NPC `buyPrice` or establish that a merchant supplies the inputs; `src/engine/actions.ts:117-119` has a separate stage/prosperity-dependent buy-price function for legacy shop goods. The preparation docs disclose that market restock and natural supply are not simulated, but the flag name still reads as an actual arbitrage result. Rename it to a direct catalog resale margin/price comparison, or include real purchase prices and supply conditions. Preserve the explicit no-market/no-natural-supply limitation in the summary.

The `masterpiece` label checks eligibility/provenance but the resulting roll may not be a masterpiece, which the prep docs correctly disclose. Long worlds advance one state continuously through 10/50/100-year checkpoints, save/reload equality, and next-day continuation equality rather than recreating worlds. Natural boss defeats are observations only; player encounter actions are explicitly absent.

The browser plan also correctly keeps normal fresh contexts on visible enabled controls without setting time/seed/RNG/state, and isolates hashed controlled localStorage fixtures. Release guards link `HEAD`, recursive `src` hashes, build status, `dist` fingerprints and served HTML/JS/CSS bytes. Errors, actual duration, Chromium version, save latency, IndexedDB, CDP heap/DOM and source-after stability are recorded; content-agent mode is explicitly deterministic policy with no model inference, and must not be called an LLM agent or human/fun/retention result. That disclosure is necessary: the deterministic policy is useful as repeatable exploratory coverage but is limited by its regex button taxonomy, small action families and control ranking. It cannot substantiate broad independent agent exploration, discover controls it cannot classify, or replace human validation. Keep the policy identity and coverage limits in the final report.

The preparation itself is correctly marked unreleased and unexecuted. Browser/runtime behavior, selectors, final catalog coverage, and production-build correlation remain unverified and require Root's final source/build freeze and lane-specific run evidence. This review does not evaluate game/catalog correctness or final J/K acceptance.
