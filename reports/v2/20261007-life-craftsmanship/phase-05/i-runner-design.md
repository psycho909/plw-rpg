# Phase 5-I distribution / economy / combat runner design

Status: authored and statically checked; the runner remains deliberately inert until Root creates an explicit I release after F, G, and H are accepted. The no-release collection check is a skip-path check, not simulation evidence. No simulation result or balance conclusion is claimed here.

## Scope and source seam

The Phase 5-I harness is a new Vitest runner beside the Phase 5 reports. It reuses the actual Phase 4 fight setup and metrics in `reports/v2/20261006-reward-core/phase-04/combat_simulation.test.ts`, including all 15 existing builds, three combat progression bands, six public/controlled targets, two policies, and eight deterministic seeds: 4,320 original metric rows and 8,640 uninterrupted/replay fight executions. Phase 5 adds controlled generated craft builds to this same matrix; it does not replace the Phase 4 builds or label old Phase 4 rows as Phase 5 evidence. The existing final JSON remains historical and keeps its original Phase 4 source commit/fingerprint.

The generator seam is `generateItem(state, { baseId, level, material, context: { kind: 'craft', recipeId } })`. Each recipe × Smithing × material profile gets one detached `createGame` state with only Smithing level set to the explicitly selected study level. Before each item, the runner resets only that state’s RNG to the profile/sample seed; generated instances are summarized and discarded, while the state’s instance sequence advances. This avoids 100,000 world constructions and preserves paired control RNG streams. This invokes the real shared craft-context rarity, affix, material-special, and (seeded Masterpiece paths, while intentionally not paying resources, consuming stamina, advancing game time, emitting action events, or creating 100,000 transaction histories. It is a distribution study of 100,000 generated craft-context items, not a claim that 100,000 complete legal crafts were performed. One item is summarized and discarded at a time; no 100,000-item object array is retained.

Phase 5-F implements the approved seeded 25% Masterpiece chance for `ironShortSword` at Smithing 6 using ordinary iron. The runner must use that real generator outcome. To isolate whether the Masterpiece marker changes combat, the matrix includes one explicitly labeled QA counterfactual made by cloning a genuinely generated Masterpiece item and setting only the clone's marker to false. It is never described as a normal in-game item or as a generated output. The normal/high-skill crafted build remains a separate actual output. G's `itemSellPrice(item)` is called on actual generated outputs only after G is accepted; the runner does not duplicate or approximate sale pricing.

## Distribution plan

The 100,000-output budget is split deterministically and as evenly as possible across 30 legal recipe × Smithing × material profiles: `starterSpear` at Smithing 1/3/6 with neutral/Fang/Moonstone (9); `fieldSpear` at 2/3/6 with neutral/Fang/Moonstone (9); `fieldArmor` at 2/3/6 with neutral/Wolf Hide (6); and `ironShortSword` at Smithing 5/6 with neutral/Fang/Moonstone (6). The levels are at or above each live recipe's `requiredSmithing`; advanced sword profiles stop at the live `practiceCap` 6. Each profile receives 3,333 or 3,334 samples, totaling exactly 100,000. The runner preflights each cell through `planCraft` using the same legal home/store/blacksmith fixture used to calculate its fee and asserts the resolved site and fee before generating any samples. These modes match the current accepted recipe registry, including F’s approved Fang/Moonstone eligibility on the advanced sword. Matched material arms reuse the same per-sample seeds within a recipe/skill stratum, providing common random numbers for material comparisons. Per-sample seeds are deterministically derived from SHA-256 of the release distribution seed plus stratum and sample index; this avoids stepping a simple adjacent seed sequence, while the resulting seeded outputs remain deterministic simulation evidence rather than a claim of true independent draws. Release seed values remain distinct from Phase 4's historical `[17,42,77,909,2026,2027,8191,9981]` fight seeds.

Each profile records counts and 95% Wilson intervals for rarity, affix count/types, special trait, Masterpiece, and sale value; the report also records mean/median/range and sample size. Rarity-weight expectations are computed from the live `craftQualityProfile` helper. Material contrasts report paired per-seed differences for target-biased-affix presence, special-trait rate, Masterpiece rate, rarity, and sale value with a paired-mean interval; exact paired sample count and raw numerator/denominator remain visible. Rarity and Masterpiece should not be presumed to change with material: the measured paired deltas are retained to catch accidental coupling. Rare tail counts (especially Legendary at 0.2%) are shown with intervals and are not over-interpreted where stratum sample sizes are small.

The economy section uses the live G `itemSellPrice`, the recipe registry, `buyPrice` in a controlled best-town / zero-trade-penalty market fixture, and the material's current store resale value as the opportunity cost of an influence material. Core's G plan now exposes `gold.required` and `station.site`; the runner calls `planCraft` at both the legal owned-home site and the normal store/blacksmith site, asserts those resolved values, and uses the lower legal plan fee for the expected-margin bound. The home fixture acquires a real home through the existing `buyProperty` action, and reports its one-time acquisition cost separately. Advanced `ironShortSword` remains blacksmith-only at its live planned fee. The economy summary includes per-output sale distribution, expected proceeds, actual planned recipe fee/input costs, influence-material opportunity cost, expected margin, first-craft margin including the home purchase, and observed upper/lower margins. It does not claim a full time/stamina economy equilibrium or a guaranteed legal sale; those require a separate player-loop scenario. Any assumptions about discounts or sale access are named in the report.

The raw distribution stream is one create-exclusive JSONL file under a run-ID-specific `i-runs/<run-id>/` directory. Each record is a compact generated-item observation (profile, sample index/seed, rarity, affixes/tier, special trait, Masterpiece, sale amount), not a full retained `ItemInstance` array. The summary report is published with `scripts.recorded_reports.write_recorded`; prior report versions and raw run directories remain preserved.

## Combat matrix extension

The exact 15 Phase 4 builds remain. Eight controlled craft arms are appended: neutral/Fang/Moonstone starter spear, neutral/Wolf Hide field armor, ordinary high-skill short sword, genuine generated high-skill Masterpiece short sword, and the same Masterpiece item's marker-cleared QA control. This yields 23 builds × 3 existing combat bands × 6 existing targets × 2 policies × 8 fresh seeds = 6,624 rows; every row has an uninterrupted fight and save/reload-every-three-turn replay, for 13,248 actual fight executions. The runner retains Phase 4's exact paired legacy comparison, target setup, progression assertions, combat accounting, and replay state/command equality checks. Craft generation uses detached deterministic RNG so all builds in a scenario retain identical fight RNG, initial HP, enemy HP, and target snapshot. Actual Adventure/elite/mini-boss/boss builds remain present in the original matrix.

The Master's marker-only pair should be combat-identical because current Masterpiece is identity/economy metadata, not a raw-stat modifier. The runner reports the observed paired outcomes and does not require Masterpiece to dominate. The generated high-skill item may itself be a Masterpiece under F's chance, so its `masterpiece` flag is reported per row.

The manifest walks every file under `src/` recursively without Git-ignore filtering (therefore includes untracked source and test files), plus this runner, the Phase 4 harness and final artifact, Phase 5 spec/recipe decisions, package manifest/lockfile, TypeScript/Vite/Vitest build inputs, and `scripts/recorded_reports.py`. The report records both Git status snapshots, manifest algorithm, runner hash, release-file hash, run ID, seed sets, and explicit output exclusions. A changed HEAD, source, harness, build input, or seed configuration aborts the run and preserves any unique partial raw output as failed evidence.

The compact summary is published through `scripts.recorded_reports.write_recorded`. A run never writes into Phase 4 directories, stamps its results with a historical source commit, or rewrites prior raw JSONL. The final report keeps separate labels for simulation, analytic expectation, controlled counterfactual, and deferred human validation.
