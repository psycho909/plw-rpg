## Current implementation contracts and likely safe integration seams

Relevant paths were inspected directly; source remains unchanged.

- `src/domain/types.ts`: canonical `GameState` currently has scalar settlement fields (`food`, `prosperity`, `safety`, `infrastructure`, growth/stage/buildings), a Goblin-oriented `threat` tuple (`monsterPopulation`, `threatLevel`, `growthRate`, `bossProgress`, `campLevel`, `bossAlive`, `warningLevel`), legacy dungeon state, and base `events/history/eventSequence`. No regional-crisis entity exists yet.
- `src/engine/simulation.ts`: `simulate(state, minutes)` rejects negative/non-finite duration, floors to whole minutes, checks safe world-time, and advances by canonical day/crop boundaries. `dailyTick` updates food/prosperity/safety/population, Goblin pressure/camp/boss warnings/spawn, NPC injuries, dungeon pressure and daily life. Threat growth is currently `growthRate - guards*.035` (bounded population), boss progress `threatLevel*.55 - guards*.04`, and settlement safety falls with threat/boss. Random NPC lifespan/immigration/injury uses `random(state)`; preserve this single RNG stream and canonical tick behavior.
- `src/engine/actions.ts`: cost-paying actions validate actor/combat/dungeon/stamina/gold before deducting then advancing time. `combatTurn` win applies loot/XP/reputation, reduces non-dungeon regional monsterPopulation by 5 and bossProgress by 10, recalculates threat/camp; Goblin chief additionally clears bossAlive/progress/warning and records memory/event. Harvest increases player food and settlement food; trade updates prosperity; existing gather gives wood/stone/iron and 4g wage; party uses 4g/day wage. Existing productive/high-leverage action seams are therefore harvest, trade, gear/inventory actions, hunt/camp, and party/NPC guard contribution.
- `src/data/config.ts`: threat levels [0,30,65], boss threshold 100, Goblin/chief definitions and settlement economy constants. `src/engine/wolfFamily.ts` is a separate controlled wolf-family system whose read projections are pure, encounter formation occurs only after eligibility and uses deterministic state RNG, snapshot is retained through flee/death/reload, and win has cooldown. ### Existing resistance and anti-hardlock logic

- There is already a deterministic-world-seed-driven autonomous Goblin chief response in `src/engine/livingEvents.ts` (`applyMediumBossAttempt`), in addition to ordinary daily guards reducing population/boss pressure. It selects an adult brave guard/mercenary not already in the party; it does nothing when the player is in combat. Success probability is clamped to 0.20–0.68 and adjusted by settlement safety. Success clears `bossAlive`, boss progress and warning level, reduces monster population by 25, raises safety by 6, records major news and a `GOBLIN_CHIEF_DEFEATED` memory shared with residents. Failure injures the selected NPC for two days, lowers safety by 2 and records regional news. Thus existing NPC autonomous boss defense/outcomes must be retained and integrated; it is incorrect to describe the game as having no autonomous outcome resolver. What is still missing is a complete canonical Regional Crisis lifecycle, explicit civilian/defense needs and preparation model, and broader persistent consequence/recovery semantics or prepared/unprepared regional balance evidence.
- Existing safeguards to preserve: state bounds and `safeInt`; action eligibility checks before payment; time/RNG atomicity in simulation tests; append-only recorded report history; legacy Goblin boss resolution path; death/succession keeps world state (save tests cover long history, deaths and successors); exact save shape and fail-closed migration validation; capped event/NPC/world histories. Do not reset/delete world on crisis defeat, consume player items before complete validation, or make fighter-only participation a hidden requirement.
- Safe seams for later slices: B can introduce one canonical Goblin crisis state and public pure eligibility/projection + deterministic daily transition; C a pure resistance/needs/outcome calculator; D/E validated atomic contribution actions (life resources vs adventure actions); F persistent consequences/recovery; G pure UI signals/projection; H major-only history/identity/succession; I controlled deterministic simulation; J regression/runtime. Keep B gated until Root accepts Phase 6-A evidence.
